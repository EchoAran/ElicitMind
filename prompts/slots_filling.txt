# EXTRACTION AND UPDATE RULES:
Extract facts solely from the interviewee's latest response in [current_turn_interaction]. Compare extracted statements against existing slots in [current_topic_slots] and apply these strict operation semantics:

1. "refine" (Compatible Elaboration & Detail Addition):
   - Use when the interviewee provides compatible elaboration, boundary details, execution steps, or supplementary specifics for an already filled slot (state="filled"), without replacing or contradicting its core value.
   - Combine the existing fact with the new detail into a coherent slot_value. For example, if a slot records "Complaint submission channels" (in-person at stations and web) and the response provides operating hours or referral boundaries for station intake, use "refine" to incorporate those hours and boundaries into the channel description (preserving the recorded channels) instead of replacing the channels via "update".

2. "update" (Initial Population of Empty Slots, Explicit Correction, or Explicit Fact Endorsement):
   - For an empty slot (state="empty"): Populate it with the confirmed fact provided in the latest response. You MUST use operation "update" (NEVER "add") when populating an existing slot from [current_topic_slots], keeping its existing slot_number and slot_key.
   - For a previously uncertain slot (state="uncertain"): If the interviewee now explicitly confirms or finalizes the value, set operation to "update".
   - For an already filled slot (state="filled"):
     * Explicit Correction/Change: When the interviewee explicitly corrects, overrides, or changes the recorded fact with a new decision, use "update" with the newly decided value.
     * Explicit Endorsement of Recorded/Prefilled Fact: When the interviewee explicitly confirms, validates, or endorses an existing/prefilled fact (e.g. agreeing that the recorded goal, audience, or scope is accurate as stated) without altering its substance, use "update" with the confirmed value. This explicitly attaches interview-grounded evidence to the slot.
     * Mere Mention without Endorsement (STRICTLY FORBIDDEN): If the interviewer's question or conversation context merely mentioned the existing value, but the interviewee did NOT explicitly endorse, confirm, or decide it in their answer, do NOT output an update! Do NOT re-emit unchanged old values without direct interviewee endorsement.

3. "add" (Brand-New Distinct Business Attribute Only):
   - Use EXCLUSIVELY when the interviewee introduces a genuinely new requirement attribute that does NOT exist anywhere in [current_topic_slots].
   - Provide a concise business attribute name in slot_key and set slot_number to null.
   - CRITICAL GUARDRAIL: NEVER use "add" for an existing slot in [current_topic_slots], even if its state is "empty"! Populating an existing empty slot is ALWAYS "update". If you specify an existing slot_number with operation "add", the system will reject your output as a contract violation.
   - Separate Attributes vs Sub-details: If an operational rule or constraint is treated as an independent attribute rather than refining an existing slot, create it via "add" with a distinct slot_key (e.g., slot_key="In-person station operating hours and intake limits", slot_number=null).
   - FORBIDDEN: NEVER overwrite, hijack, or replace an existing slot whose slot_key represents a different business concept! For example, do not overwrite a "Submission Channels" slot with "Operating Hours". Distinct attributes MUST be created via "add" with slot_number=null.

4. "conflict" (Direct Contradiction with Existing Recorded Scope or Decisions):
   - Use when the interviewee's latest statement directly contradicts, negates, or conflicts with a previously recorded fact or scope decision in [current_topic_slots] without explaining why the scope changed.
   - Specific Scope Contradiction: If an existing scope slot states that a capability is OUT OF SCOPE or NOT SUPPORTED for the initial release (e.g. "First version does not support citizen self-submission"), but the interviewee's latest response asserts that it IS supported or included in the first release (e.g. "First version citizens can submit complaints through basic web screen"), you MUST target that existing scope slot, set operation to "conflict", and put the contradictory statement in slot_value. Do NOT silently ignore the conflict or treat it as an independent addition.

5. "mark_uncertain" (Tentative or Provisional Value):
   - Use when the interviewee provides a concrete candidate value but explicitly expresses that it is tentative, subject to confirmation, or might change (e.g., "Tentatively 30 days, awaiting legal review").

6. "defer_uncertain" (Explicit Postponement / Deferral):
   - Use when the interviewee explicitly chooses to defer, postpone, or leave this requirement undecided for now (e.g., "defer for later", "undecided at this moment", "leave tentative").
   - If the slot already has a value, preserve it in slot_value; if empty and no candidate exists, set slot_value to null.
